API Documentation

Forcepoint DLP Protector File Scanner
Back to scanner

Internal HTTP API served by this app's own Backend. There is no authentication and no API key — it's meant to be reached only from this app's own frontend or from other services on the same trusted network. It never exposes the Protector's host, port, or token directly.

Health

Check whether this server is up and whether the Protector is reachable

GET /api/health Server uptime + a quick TCP reachability check against the Protector

This only opens a TCP connection to the configured Protector host/port to confirm it's reachable — it does not send a real inspection request. The Protector's host/port are never included in the response, same as everywhere else in this app.

Example response — 200 OK
{
  "status": "ok",
  "uptimeSeconds": 3600,
  "timestamp": "2026-08-17T20:29:36.751Z",
  "protector": {
    "reachable": true,
    "checkedInMs": 11
  }
}

When the Protector can't be reached, protector.reachable is false and an error field is included (e.g. "ECONNREFUSED"). This endpoint itself always responds 200 — check the nested field, not the HTTP status.

Scan

Send a file to be inspected by the Forcepoint Protector

POST /api/scan Scans a file against the configured DLP policy and returns the verdict
Request body — multipart/form-data
FieldTypeDescription
filebinaryrequiredThe file to scan. Rejected above the configured max size.
Example response — 200 OK
{
  "globalMessageId": "bfdfb88a-1d7a-4eba-9f24-7c6beb571d7d",
  "resolution": "MATCHED",
  "violations": [
    {
      "policyId": "29017",
      "policyName": "BulwarxTestKeyWord",
      "rules": [
        {
          "ruleId": "rule_29017",
          "ruleName": "BulwarxTestKeyWord",
          "severity": "MEDIUM",
          "matches": 1
        }
      ]
    }
  ],
  "actions": ["Block"],
  "maxNumberOfMatches": 1,
  "elapsedMs": 80,
  "fileName": "file.txt",
  "fileSizeBytes": 73
}
Status codes
200Scan completed — check resolution/violations for the verdict
400No file sent, or the file failed to parse
413File exceeds the configured maximum size
502Unable to reach the Protector, or it returned an error
504Timed out waiting for the Protector to respond

Settings

Read or update the runtime-configurable scan settings

GET /api/settings Returns the current settings — both the raw per-field state and the effective values in use
Example response — 200 OK
{
  "fields": {
    "maxFileSizeMb": { "enabled": false, "value": 30 },
    "requestTimeoutMs": { "enabled": true, "value": 300000 },
    "hostIps": { "enabled": false, "value": "" },
    "hostName": { "enabled": true, "value": "Amit-Agent" },
    "destinationHttpUrl": { "enabled": false, "value": "https://dlp-client.local/upload" },
    "destinationHttpHostname": { "enabled": false, "value": "dlp-client.local" }
  },
  "effective": {
    "maxFileSizeMb": 30,
    "requestTimeoutMs": 300000,
    "hostIps": "",
    "hostName": "Amit-Agent",
    "destinationHttpUrl": "https://dlp-client.local/upload",
    "destinationHttpHostname": "dlp-client.local"
  }
}

fields is the raw per-field on/off state (what the Settings screen shows). effective is what actually gets sent to the Protector on the next scan — a disabled field falls back to its server-side default or auto-detected value.

POST /api/settings Updates one or more settings fields — only the fields included in the body are changed
Request body — application/json
FieldTypeDescription
maxFileSizeMb{enabled, value}Value: 1–500
requestTimeoutMs{enabled, value}Value: 1000–300000
hostIps{enabled, value}Comma-separated IP list
hostName{enabled, value}Max 253 characters
destinationHttpUrl{enabled, value}Must be a valid http(s):// URL
destinationHttpHostname{enabled, value}Max 253 characters
Example request
{
  "hostIps": { "enabled": true, "value": "10.20.4.51" }
}
Status codes
200Saved — response body is the same shape as GET /api/settings
400One or more values failed validation (see error for which fields)

Direct to Protector

Bypass this app's own scan logic and talk to the Protector's Inspection API directly

POST /api/protector/raw Relays your own metadata + file straight to the Protector, unprocessed

This still goes through this app's backend — the Protector's host, port, and token are never exposed to the browser — but it skips this app's own metadata construction (Settings, source auto-detection, response reshaping) entirely. You write the raw metadata yourself and get back the Protector's raw, unprocessed response. See DEVELOPER.md for the exact request format and the file-wrapping gotcha demonstrated below.

Request body — multipart/form-data
FieldTypeDescription
metadatatextrequiredRaw metadata JSON (context/contentDescriptors/source/destinations) — not built by this app
filebinaryrequiredThe file to send
wrap"true"/"false"Default true. Set false to send raw file bytes instead of the HTTP-wrapped envelope — demonstrates why it always reports 0 matches
